Scope: security, stability/concurrency, UI/UX, deployment samples, build system.
Method: code reading of all of `src/`, `scripts/`, `samples/`, `data/`, `c64/`;

## 1. Executive summary

**Memory safety / RCE: nothing exploitable found.** The 1.2.x fixes are real and
hold under fuzzing. Every hot path fed by a remote caller or by the serial side
(telnet subnegotiation, `parse_ip_data`, ip232 de-stuffing, gate password buffers,
the 8 KB HTTP request/response buffers and the `strncat` JSON builder, the exec
and webhook argument construction) was fuzzed on the ASan+UBSan binary with
boundary-length and all-256-byte inputs and produced **zero** overflow,
use-after-free, out-of-bounds or format-string reports. Two UBSan hits exist,
both low impact: a signed-integer overflow in the AT number parser (value is
bounds-checked after the fact, so no OOB results) and a misaligned load in the
legacy `gethostbyname` code (benign on x86-64/arm64). One formal UB is more
consequential: an unguarded `FD_ISSET(-1)` in ip232 mode that glibc's
`_FORTIFY_SOURCE=2` turns into an abort on Linux.

**The real risk is architectural, not memory corruption:**

1. In ip232 (`-v`) mode the "C64" side is a TCP listener on **0.0.0.0 with no
   authentication**. Whoever reaches it is the trusted modem owner: confirmed
   open TCP proxy / SSRF via `ATDT host:port`, BBS impersonation to real
   callers, and lock-out of the legitimate VICE client.
2. Worker threads call `exit()` on recoverable conditions. A USB-serial glitch
   kills the whole process within 100 ms (the advertised auto-reconnect can
   never run), and a gate-success hook (`-E`) that outlives its 30 s timeout
   kills tcpser via SIGALRM's default action. Both confirmed.
3. Serial writes silently drop bytes under backpressure (non-blocking fd, short
   writes ignored by every caller). Confirmed: 200 of 20 000 bytes delivered.
4. `ATZ`/`AT&F` (the first thing every C64 BBS sends) wipe the operator's wiring
   flags (`-I`, `&C0`, `&K`) and never reply OK. Regression from the 1.2.1 round.
5. The flagship sample deployment is broken: the hardened systemd unit uses
   three wrong flags (`-w 8080` is the watchdog, `-B` sends the *blocklist* to
   callers as the busy screen, `-E` is given a directory), the installer writes a
   config file tcpser never reads, the gate scripts validate `$1` that is never
   passed, and the nginx sample is rejected by `nginx -t`.
6. UI/UX: both dashboards fail the sysop's first question ("is someone on my
   BBS right now, on which line, what are they seeing?"). The web API never
   exposes live link state; the TUI shows one line, flickers on a full clear
   every 2 s, ignores `TERM`, and its `q` key is a raw `exit(0)`. The CLI
   silently accepts almost any bad input, including `-k ""` which locks every
   caller out.

## 2. Findings

IDs: SEC = security, STAB = stability, UX = user experience, DEP = deployment/
samples, BLD = build. Each entry: file:line → problem → trigger/impact → fix.

### 2.1 Memory-corruption / RCE class (ranked first by owner request)

**None exploitable.** Items in this class, all UBSan-grade:

- **SEC-M1 · Signed integer overflow in AT number parser** — `src/getcmd.c:72`
  — CONFIRMED (UBSan). `num = num*10 + digit` with no guard; `ATS2=99999999999999999999`
  triggers `signed integer overflow: 999999999 * 10`. Result is only used as an
  S-register index/value and every consumer bounds-checks (`num>=0 && num<100`),
  so no OOB. Remotely reachable only via the ip232 side (SEC-H1).
  Fix: accumulate in `long long`, clamp or return `-1` (ERROR) on overflow.
- **SEC-M2 · Misaligned load from `gethostbyname`** — `src/ip.c:139` —
  CONFIRMED (UBSan). `*((struct in_addr*)hp->h_addr)`. Benign on current ABIs.
  Fix: `memcpy(&cin_addr, hp->h_addr, sizeof cin_addr)`; better, move to `getaddrinfo`.
- **STAB-H5 · `FD_ISSET(-1)` on the serial fd in ip232 mode** — `src/bridge.c:1493`
  (`FD_SET` at 1342-1345 is guarded by `is_connected`, `FD_ISSET` is not; fd is
  `-1` from `dce.c:16` until a VICE client attaches) — CONFIRMED UB; abort on
  glibc with the Makefile's `-D_FORTIFY_SOURCE=2` by analysis (`__fdelt_chk`
  → "buffer overflow detected"). Trigger: a caller hits `-p` (or a dashboard
  hotkey fires) before anything connects to `-v`. macOS masks it, which is why
  it never crashed here. Fix: `if(cfg->dce_data.is_connected && fd >= 0 && FD_ISSET(...))`;
  audit all `FD_SET/FD_ISSET` sites for `fd<0` and `fd>=FD_SETSIZE`.

Explicitly tested and **clean**: `nvt.c` subnegotiation (`resp[100]`, truncated/
oversized SB, NAWS edge lengths); `bridge.c parse_ip_data text[1025]` at exactly
1024/1025 bytes and 600× IAC-IAC runs; `ip232_read` de-stuffing under random
binary flood; gate `pwbuf[128]`/`filtered[256]` with 127/128/200-char passwords,
200 000-byte no-CR line, 200 pipelined guesses, IAC interleaved; web
`get_status_json`/`json_ascii_preview`/SSE with all 256 byte values and quotes
with `TCPSER_DASH_TRAFFIC=1`; `secure_script.c` and `webhook.c` argv/env
construction (only caller-derived value is an `inet_ntoa` dotted quad); all
`LOG`/`printf` format strings.

### 2.2 High

- **SEC-H1 · ip232 listener binds 0.0.0.0 with no auth → open proxy / SSRF** —
  `src/ip232.c:71` → `ip_init_server_conn(cfg->tty, 25232)` with no bind
  address → `src/ip.c:68-73` `INADDR_ANY` — CONFIRMED. From the ip232 port,
  `ATDT127.0.0.1:19999\r` made tcpser open an outbound TCP connection and relay
  bidirectionally (victim banner returned to the attacker). Also: attacker
  becomes "the BBS" for real callers; first connection wins (`ip232.c:46`) so
  the real VICE is locked out. The web dashboard got loopback-by-default
  hardening; this side did not. Fix: default to `127.0.0.1`, add
  `TCPSER_IP232_BIND`, loud warning when non-loopback; consider restricting
  `ATDT` targets in ip232 mode.
- **STAB-H1 · `ctrl_thread` exits the process on any TIOCMGET failure; USB
  reconnect unreachable** — `src/bridge.c:1159-1194` (`exit(-1)` at 1193),
  `src/serial.c:215-221`, `src/dce.c:133-147` — CONFIRMED (pty test: process
  died rc=255 1.5 s after the port stopped answering ioctls). Reconnect logic at
  `bridge.c:1196-1222, 1388-1396, 1496-1504` never runs. Fix: never `exit()`
  from a worker; on `-1` mark serial lost, post `MSG_SER_LOST` to the bridge
  pipe, wait for reconnect, re-read status; treat `ENOTTY` as "no control
  lines" so ptys work for testing; update `dashboard_set_serial_fd` after reconnect.
- **STAB-H2 · Serial TX bytes silently dropped under backpressure** —
  `src/serial.c:113` (`O_NONBLOCK` never cleared), `serial.c:14-30` (`write_all`
  returns short on EAGAIN), `src/modem_core.c:200-204` (`mdm_write` is `void`),
  callers `bridge.c:851, 1083, 1090, 1093` — CONFIRMED: 20 000 bytes caller→BBS
  with the C64 side stalled 2 s → 200 bytes received. At 2400 baud a 10 KB
  paste loses ~6 KB; large-window protocol uploads corrupt. Fix: clear
  `O_NONBLOCK` after open (reads already go through `select`), or `poll(POLLOUT)`
  with timeout on EAGAIN; make `mdm_write` return `int` and count drops. Same
  for `writeFile()` (STAB-L8).
- **STAB-H3 · Gate hook `-E` is synchronous and its timeout kills tcpser** —
  `src/secure_script.c:192-223` (`SIGALRM` set to `SIG_DFL`, `alarm(30)`,
  blocking `waitpid`) — CONFIRMED (harness and ASan server both exit 142 =
  SIGALRM). Additionally `src/tcpser.c:101` ignores SIGCHLD, so `waitpid`
  returns `ECHILD` and *every* hook run is logged as "waitpid failed" /
  "Script execution failed" even on success (CONFIRMED). Comment at
  `bridge.c:728` and README/man say "async"; it blocks the connection thread
  (no RING until the hook finishes). `alarm()` is process-wide, so two modems
  clobber each other. Fix: double-fork or a helper thread so the hook is truly
  async; timeout via `waitpid(WNOHANG)` polling or `timer_create`, never
  `alarm`+`SIG_DFL`; build `envp[]` before `fork` and use `posix_spawn`/`execve`
  with no logging between fork and exec (STAB-M7).
- **STAB-H4 · `ATZ` / `AT&F` wipe wiring flags and never answer OK** —
  `src/modem_core.c:634-673` (resets `invert_dcd/force_dcd/force_dsr/invert_dsr`,
  `dce_set_flow_control(0)`, then `done = TRUE` skips the `AT_CMD_END` OK at
  424-428), `674-708` same for `&F` — CONFIRMED (`-I` then `ATZ`: DCD flipped
  from 1 to 0; client received only the echo). Introduced by commit 775783c
  (1.2.1). Breaks the init sequence every C64 BBS sends. Fix: capture an
  operator profile (`invert_*`, `force_*`, flow control, `-i`) at startup and
  have ATZ/&F restore *that*; fall through to the OK path. Factor the four
  divergent copies of factory defaults (`mdm_init_config`, ATZ, &F,
  dashboard `MSG_RESET` at `bridge.c:1586-1612`) into one `mdm_reset_profile()`.
- **UX-H1 · Silent acceptance of invalid CLI input, incl. `-k ""` lockout** —
  `src/init.c:200-215` (no emptiness check) vs gate requiring `pwlen > 0`
  (`bridge.c:692`) — CONFIRMED: every caller is rejected forever, no message.
  Also accepted silently: `-s 12345`, `-s abc` (banner shows `@ 0 baud`),
  `-H abc`/`-H 0` (dashboard silently off), `-H 80` prints `Web: http://…`
  after bind *failed* (failure is `LOG_ERROR`, default level is FATAL),
  nonexistent `-P/-G` files, `-e notaurl`, `-t Q`, `-l 9`, `-m -5`; clamps for
  `-W/-w` are `LOG_WARN` and never shown. Fix: validate at parse (baud via
  `ser_get_bps_const`, ranges, `stat()` files, non-empty password), print
  clamps to stderr unconditionally, print `Web:` only after a successful bind.
- **UX-H2 · Illegal option prints full help and exits 0; help to stderr** —
  `src/init.c:355-357` (`?` treated as `h`) — CONFIRMED. `--help` first says
  `illegal option -- -`. Fix: usage line + exit 2; help to stdout; add long options.
- **UX-H3 · Web dashboard has no live link state** — `src/webserver.c:224-284`
  emits counters/history/traffic only; `g_dash` has `connected, peer_ip,
  session_start, dcd_on, dsr_on, tty, speed, port, modem_count`
  (`dashboard.h:28-39`) none exposed; history is written only at call *close*
  (`dashboard.c:720-737`). Header reads "Connected" meaning the SSE socket.
  Fix: expose a `lines[]` array and render it first (see §3).
- **UX-H4 · SSE closes every 5 min → false "Connection lost"; 16 open tabs =
  503 for everyone incl. Prometheus** — `webserver.c:410-417` (60×`sleep(5)`),
  `onerror` at 211-213 never cleared, `MAX_WEB_HANDLERS=16` — CONFIRMED.
  Fix: keepalive comment every 15 s, `retry:` hint, clear the banner on
  `onopen`, separate SSE budget from one-shot requests.
- **UX-H5 · TUI `q` is `exit(0)`; `H`/`U` fire instantly on adjacent keys** —
  `src/dashboard.c:790` — CONFIRMED. Bypasses graceful shutdown
  (`tcpser.c:322-339`): live caller gets no NO CARRIER, up to 60 s of `-Y`
  stats lost; no `atexit(term_restore)` so any worker `exit(-1)` leaves the
  terminal raw. Fix: set `g_running=0` and return; `y/n` confirm for q/u/h.
- **UX-H6 · TUI ignores `TERM`/`NO_COLOR`/isatty and full-clears every 2 s** —
  `dashboard.c:206` (`ESC[2J ESC[H` per frame), plus a full `render()` on every
  stat event (687, 701, 716, 735); `TERM=dumb` output byte-identical to xterm
  (395 256-colour sequences/frame); hardcoded Unicode glyphs (72-80);
  `W<60→60,H<20→20` clamp then 23 rows drawn (192-200) so 80×24 gives Traffic
  and History **2 rows each** — CONFIRMED by pty capture. Fix: diffed cell
  buffer, capability tiers, adaptive layout (see §3).
- **DEP-H1 · Hardened sample systemd unit cannot work as shipped** —
  `samples/systemd/tcpser.service:8-13` (copied by `install_secure.sh:193`) —
  CONFIRMED. `-w 8080` = watchdog seconds (no dashboard starts); `-E
  /usr/local/tcpser/scripts` = rejected (`-E` takes a name); `-B
  …/tcpser.blocklist` = the **blocklist is sent to callers as the busy
  screen**; `-P/-G` point at the scripts dir, `.seq` files are installed to
  `/usr/local/share/tcpser/`; no `Environment=TCPSER_BLOCKLIST` so the default
  relative path resolves against CWD `/` which is read-only under
  `ProtectSystem=strict` → **permanent blocks are never persisted**.
  `data/tcpser.service` (the one `make install` ships) runs as **root** and
  names non-existent files in `ReadWritePaths=` (namespace failure, exit 226).
  `install_secure.sh:156` writes `/etc/tcpser/tcpser.conf` which **tcpser never
  reads**, and overwrites it and the unit on every run. Fix: corrected
  `ExecStart` (see DEP section of the agent notes: `-H 8080`, `-P/-G` to
  share dir, `-E gate_success_log`, `Environment=TCPSER_BLOCKLIST=/var/lib/tcpser/…`,
  `StateDirectory=`, `User=tcpser`, `DeviceAllow=`), drop or implement the conf file.
- **DEP-H2 · All sample gate scripts fail on every run** —
  `samples/scripts/gate_success_{log,notify}:7`, `gate_fail_security:7` validate
  `$1`; tcpser passes `argv={name,NULL}` and the IP only in `TCPSER_PEER_IP`
  (`secure_script.c:140,173`) — CONFIRMED. `gate_fail_security` can never be
  invoked (no failure hook exists). Fix: `CLIENT_IP="${TCPSER_PEER_IP:-}"` as
  `scripts/*.sh` already do; delete/mark the fail script.
- **DEP-H3 · nginx sample rejected by `nginx -t`; iptables rate limits are
  dead** — `samples/nginx/tcpser.conf:52` (`limit_req_zone` in `server{}`),
  66-67/72-73 duplicate directives; `samples/firewall/iptables-rules.sh:32,39`
  accept all NEW before the `-m recent` rules at 35-36/42-43; no ip6tables —
  CONFIRMED. `samples/firewall/ufw-rules.sh:15` runs `ufw --force reset`
  (wipes every other rule on the host).

### 2.3 Medium

- **SEC-MED1 · `Access-Control-Allow-Origin: *` on the dashboard** —
  `src/secure_http.c:242` — PLAUSIBLE. Default is loopback with no token, so any
  web page the operator visits can `fetch()` caller IPs/history (and session
  content with `TCPSER_DASH_TRAFFIC=1`). Fix: remove the header (UI is same-origin).
- **SEC-MED2 · Token-in-URL auth** — `webserver.c:154-156, 347-353` — lands in
  browser history, screenshots, nginx access logs that fail2ban then reads
  (`samples/fail2ban/tcpser.conf:8`). Also the path validator runs *before*
  the `?` split, so tokens containing `..`, `//`, `%2e` are rejected, and a
  bad path logs the full URL incl. token at `LOG_ERROR`. Fix: `GET /?token=X`
  → `Set-Cookie: HttpOnly; SameSite=Strict` + 302; accept cookie or token;
  nginx `log_format` with `$uri` not `$request`.
- **STAB-M1 · `log_trace()` unlocks a mutex it doesn't hold when `len % 16 == 0`** —
  `src/debug.c:125-137` (`log_end()` outside the `if(i>0)`) — CONFIRMED (16-byte
  trace line followed by stray blank line). pthread return checks at 46/158/174
  test `== -1` and can never fire. Fix: move `log_end()` inside; test `!= 0`.
- **STAB-M2 · `log_reopen()` (SIGHUP/logrotate) swaps `log_file` without the
  lock** — `debug.c:66-75`, called from `tcpser.c:249` — PLAUSIBLE UAF of the
  old `FILE*` by a thread mid-`LOG`. Daily event under systemd `ExecReload`.
- **STAB-M3 · Cross-thread modem state with no synchronization** — TSan: 7
  distinct racy pairs in a 10 s session (`dce.fd/is_connected` ip232.c:54-57
  vs bridge.c:1262/1493; `conn_type` modem_core.c:364/275 vs bridge.c:1114;
  `is_cmd_mode` 850 vs 1115; `line_data.fd/is_connected` line.c:73/76 vs
  bridge.c:1129; main thread peeks `cfg[i]` at tcpser.c:278-299) — CONFIRMED.
  Fix: one mutex per `modem_config` or `_Atomic` for the handful of shared
  fields; main should consume state via the pipe, not peek.
- **STAB-M4 / SEC-LOW1 · fd-reuse window in `line_disconnect`** — `line.c:103-110`
  closes before clearing state; `ip_thread` (`bridge.c:1129-1146`) can `recv()`
  on a number reused by another accept (web client, next caller) and forward
  foreign bytes to the C64; `select()` error path (1123-1126) spins with no
  backoff — PLAUSIBLE. Fix: clear state, `shutdown()`, let the reading thread close.
- **STAB-M5 · Watchdog re-arms forever** — `bridge.c:1462-1482` — a healthy but
  silent BBS gets a DTR pulse every `-w` seconds and a BREAK every third time,
  indefinitely; README describes a one-shot. Fix: cap attempts, back off, surface on dashboard.
- **STAB-M6 · Stats save/load read `g_dash` unlocked** — `dashboard.c:804-885`
  from the main thread — PLAUSIBLE torn writes to the stats file.
- **STAB-M7 · `fork()` in a multithreaded process then `setenv`/`LOG`** —
  `secure_script.c:134-188`, `webhook.c:64-86` — PLAUSIBLE child deadlock
  before exec (webhook silently lost; gate hook → STAB-H3 fires).
- **STAB-M8 · Modem in `serial_reconnect()` still routable; `accept_pending`
  freezes all ports** — `tcpser.c:276-301` vs `bridge.c:1200-1222` — PLAUSIBLE
  (shadowed by STAB-H1 today).
- **UX-M1 · Live traffic unreadable for a C64 BBS** — `webserver.c:47-56`

- **UX-M3 · TUI loses the startup summary and all logs** — the config block

  dead and `close(0)` at shutdown (`tcpser.c:83, 340`).
- `writeFile()` turns `-1` into `SIZE_MAX` and continues (`util.c:23-40`).
- Non-reentrant libc in threads: `strtok`/`gethostbyname` (`ip.c:115-132`),
  `localtime()` (`util.c:87`, `webserver.c:245`), `rand()`; `blocklist_path()`
  static buffer used outside its mutex (`bridge.c:157, 345`).
- Serial: no `TIOCEXCL`; `cfsetispeed/ospeed` unchecked (`serial.c:142-143`);
  `ser_set_control_lines` returns 0 on failure (252-255); `tcsendbreak` on an
  ip232 socket (`bridge.c:1477`).
- `-M` with a non-tty stdin that never EOFs blocks the main accept loop (`dashboard.c:783`).
- `contains_path_traversal` rejects any `/.` so `TCPSER_BLOCKLIST=/home/pi/.tcpser/…`
  is refused (`secure_paths.c:27-33`); NUL loop at 43-45 can never match.
- `ip_init_server_conn` `strtok`s the caller's address in place → truncated
  startup banner (`ip.c:31-36`).
- Web: single `read()` per request (split requests → 400); `HEAD /metrics` → 404;
  `strncat` truncation would yield invalid JSON and stall the SSE client;
  HSTS header sent over plain HTTP; path check allows `%2E` (uppercase) —
  harmless since routing is `strcmp`-based.
- Password gate lowercases and strips bit 7 of both sides (`bridge.c:437-448`) —
  by design for PETSCII, reduces entropy; document it.
- AT command line logged verbatim at `-l 5+` (`modem_core.c:403`) → ANSI/log
  injection from the ip232 side. Sanitize non-printables.
- `signal()` instead of `sigaction`; `gethostbyname` IPv4-only; 32-bit Pi `time_t` (Y2038).
- Build: no header dependency tracking (`touch src/modem_core.h; make` rebuilds
  nothing); `makedepend` target dead. Fix: `-MMD -MP` + `-include $(OBJS:.o=.d)`.
- `make uninstall` `rm -rf`s the data dir that holds `connections.csv` and the
  appended blocklist. `data/tcpser.blocklist` ships three real IPs as the default.
- `data/com.tcpser.bbs.plist` runs as root; `-L` and `StandardErrorPath` both
  target `/var/log/tcpser.log` (two writers).
- `health_check.sh` false alarms (`set -e` + multi-PID `pgrep`, `netstat -p`).
- Logs written by sample scripts are world-readable (umask) while the C side
  uses 0600 for the same PII.
- Shell hygiene: no `set -u`/`pipefail` anywhere; `grep -c "$CLIENT_IP"` with
  unescaped dots over-matches (`gate_fail_security:29`).
- fail2ban cannot protect the modem port: the gate-fail log line
  (`bridge.c:948`) contains no IP. Add it.
- C64 tool (`c64/`): coherent v0.1; probes `$DE00` only (Turbo232 at `$DF00`
  shows NONE); not linked from README/docs index; `R` = RTS vs TUI `R` = Reset.

## 3. UI/UX assessment and redesign direction

**Verdict.** The engineering underneath is better than the surfaces on top of
it. The identity (cyberpunk / demoscene) is right for the audience and `-h` is
genuinely good, but the neon is applied to every word, both dashboards miss the
sysop's first question, C64 traffic is rendered as dot-soup, and nothing
identifies *whose* BBS this is. Colour contrast of body text is mostly fine;
the problems are hierarchy, state, robustness and truth.

**Design stance.** Neon as *accent and signal*, not body colour: cyan for the
title, LIVE and carrier; magenta for section titles; everything else near-white
/ blue-grey. Glow only on title and carrier state. Scanlines opt-in, off under
`prefers-reduced-motion`. One PETSCII renderer in C shared by both dashboards.

## 4. Maintainability

Longest functions: `bridge_task` 395 lines (`bridge.c:1224`), `mdm_parse_cmd`
374 (`modem_core.c:391`), `analyzer_run` 332, `main` 271 (`tcpser.c:73`),

×2; no-answer branches ×2 and DTR-kick sequences ×3; gate and baud-menu

split: `bridge.c` → `blocklist.c`, `gate.c`, `bridge.c`, `bbs_watchdog.c`;
`dashboard.c` → `dashboard_state.c` (locked accessors), `dashboard_tui.c`,

**Tests: none.** Minimal harness that fits this code: (1) `make check` running

## 5. What is done well (keep)

- Memory discipline: fixed buffers with explicit clamps everywhere the 1.2.x
  work touched; no heap in the hot path; ASan/UBSan clean across a full session.
- `secure_script.c`: `lstat` + `O_NOFOLLOW` + descriptor re-validation +
  `fexecve`, fixed argv, scrubbed env, fixed PATH — textbook TOCTOU-proof exec.
- `webhook.c`: secret URL via `-K -` on stdin (not in `ps`), `execlp` (no
  shell), payload fields are not attacker-controlled.
- Web UI uses `textContent` (no DOM XSS, verified); `json_ascii_preview`
  escapes correctly; CSV log writes only numeric IP + fixed strings; PII files
  0600; constant-time compares; dashboard loopback-by-default with warnings.
- Pipe-based thread wakeups are simple and robust; accept gate released right
  after `accept()`; correct EINTR/partial-write loop in `ip_write`/`write_all`.
- Build hardening (`-fstack-protector-strong`, `_FORTIFY_SOURCE=2`, PIE, full
  RELRO on Linux); warning-free; `DESTDIR`/`PREFIX` honoured.
- `-h` text is grouped, shows defaults, has quick start and examples.
- Code comments next to prior fixes explain bug and trigger — made this audit faster.
