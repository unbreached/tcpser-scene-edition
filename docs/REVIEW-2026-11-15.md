# TCPSER Scene Edition 1.4.1: review and priority list (2026-11-15)

Scope: stability, security, protocol/modem emulation, features, UI and
graphics, project infrastructure. **Nothing was changed by this review**; it
is a work list. It follows on from [`AUDIT-2026-11-01.md`](AUDIT-2026-11-01.md)
and lists only what is still open or new in the current tree (commit `50a966b`).

Method: three passes. Security and stability/protocol were each reviewed
independently against the source and exercised on scratch builds (normal,
ASan/UBSan, ThreadSanitizer) in ip232 mode with scripted callers; UI, features,
docs and build were reviewed by reading the code and the shipped screens. The
findings quoted here were spot-checked against the source afterwards.

Marking: **RUN** = reproduced on a running instance, **CODE** = unambiguous
from the source but not executed, **PLAUSIBLE** = mechanism clear, not
reproduced. Effort: S = hours, M = a day or two, L = several days.

> **Status (2026-11-15, release 1.4.2):** every finding in section 2 is
> fixed, each with a regression test where one could be scripted (16 tests;
> `make check`, `check-asan` and `check-tsan` pass), except these, which are
> left open on purpose:
>
> - **F-30** (control-line pulses with `-I`): the current pulse is deliberate
>   and changing it needs a real cartridge to judge; not touched.
> - **SEC-3** (no `ATD` dial allowlist), **SEC-6** (case-insensitive gate
>   password), **SEC-8** (no self privilege drop; launchd plist runs as root):
>   design decisions, documented in `SECURITY_CHANGELOG.md`.
>
> Section 3 (improvements and new features) is not started, apart from what
> the fixes needed: distinct dial results (`BUSY` / `NO ANSWER`), `&D3`, the
> caller's terminal type in the log, `--answer-timeout`, `--web-host`.

---

## 1. Summary

- **Memory safety / RCE: nothing found.** Every path fed by a caller, the
  ip232 peer, the serial side, an HTTP client or the config file was walked
  for overflows, off-by-one, signedness, unterminated strings and `fd_set`
  misuse. The earlier fixes hold.
- **The weak area is now modem and telnet behaviour, not crashes.** Twelve
  Medium-or-higher stability findings were reproduced. Most have the same two
  roots: the per-line bridge thread does blocking work (gate, dial, writes to
  the caller), and the telnet layer keeps no state between reads.
- **Security is in good shape by default.** The one finding worth acting on
  soon is that the web console does not check the `Host` header, so a hostile
  web page can read caller data from a loopback-only console by DNS rebinding.
- **Two advertised things do not work:** "timed blocks" (the unblock action in
  both UIs has nothing to clear) and `-m` max session time on an idle caller.
- **Biggest opportunities:** a robust telnet layer (fixes file transfers), a
  live C64 screen mirror in the web console, IPv6, and CI with release builds.

## 2. Priority list

### P1: fix first (callers are lost, lines get stuck, data is corrupted)

| # | ID | What | Evidence | Effort |
|---|----|------|----------|--------|
| 1 | F-01 | A failed `ATD` leaves the modem off-hook in data mode. Every incoming caller gets BUSY until the C64 sends another byte, and that next command is swallowed. | RUN | S |
| 2 | F-07 | A caller that stops reading wedges the line: writes to the caller block on the bridge thread with no timeout, so DTR hangup, `-m` and dashboard hangup cannot run. | RUN | M |
| 3 | F-05 | No telnet parser state across reads. An `IAC` split over two reads drops or leaks bytes into the BBS (0x18 CAN aborts XMODEM); binary uploads corrupt whenever 0xFF straddles a read. | RUN | M |
| 4 | F-04 | With `-x` or `-k` the gate eats the client's opening telnet negotiation, so the session is treated as raw: no IAC handling in either direction for the whole call. | RUN | S |
| 5 | F-03 | Parity starts as "unknown" (-1) and is treated as "parity on". Until the C64 types its first `AT`, tcpser refuses telnet BINARY and strips bit 7, which breaks PETSCII graphics after a tcpser restart. | RUN | S |
| 6 | F-09 | `-m` (max session time) is only checked when the line has activity. An idle caller is never cut. | RUN | S |
| 7 | F-08 | Banner, gate and baud menu run on the line's bridge thread. While a bot idles in the gate, the C64's `AT` commands wait (19 s measured), as do DTR, SIGTERM and dashboard hangup. | RUN | M |
| 8 | F-06 | `ATD` does blocking DNS and `connect()`. An unreachable host stalls the line for the OS timeout; S7 is ignored and a keypress does not abort. | RUN | M |
| 9 | F-10 | `ATD` while an inbound call is ringing overwrites the caller's socket without closing it: leaked fd, caller hangs silent forever. | RUN | S |
| 10 | SEC-1 | Web console has no `Host` header check. With the default loopback bind and no token, a web page using DNS rebinding can read `/api/status` (caller IPs, history, and session content if `--web-traffic` is on). State-changing POSTs are not affected. | RUN | S |
| 11 | F-23 | "Timed blocks" do not exist: `blocked_until` is never set, so `U` in the TUI and F9 / `POST /api/unblock` in the web console do nothing. The 512-slot table is shared by blocks and rate tracking; blocklist lines beyond it are ignored silently. | CODE | M |

Items 2, 7 and 8 share one fix direction: make the caller socket non-blocking
and move the pre-connect phase and the dial into the select loop (or their own
thread). Items 3, 4, 5 and F-12/F-22 below are one piece of work: a
per-connection telnet state machine with RFC 1143 option state.

### P3: when convenient

- **F-22** telnet details: `DO ECHO` answered every time (no option state),
  server-role options volunteered on outgoing calls, CR NUL not handled.
- **F-29** control lines polled every 100 ms; a shorter DTR pulse is missed.
- **F-30** "pulse to 0" steps read as carrier-present with `-I`.
- **F-31** only the first byte of a coalesced pipe message is handled.
- **F-32** listeners are blocking after `select` (macOS/BSD reset-in-queue stall).
- **F-33** no `TCP_NODELAY`; no keepalive on outgoing calls; web threads lack
  the signal mask; stats file not written via temp + rename; connection-log
  byte counts are always 0; serial termios not restored on exit.
- **SEC-3** no dial allowlist: whoever drives the C64 side can `ATDT` anywhere,
  including 127.0.0.1. Safe by default (ip232 binds loopback), an open proxy if
  `--ip232-bind` is made reachable.
- **SEC-6** gate password is compared case-insensitively with bit 7 stripped
  (documented; could be optional).
- **SEC-7** web handler pool (16) has no per-IP cap.
- **SEC-8** the process never drops privileges itself; the launchd plist runs
  as root by default.
- **Build:** `CC = gcc` is hard-coded while the sanitizer targets need clang;
  `make install` overwrites an existing `tcpser.conf` and `tcpser.blocklist`
  in the data directory.

## 3. Improvements and new features

Ordered by value to a C64 BBS sysop within each group.

### 3.1 Protocol and modem emulation

1. **Telnet layer rewrite** (state machine, RFC 1143 option state, role-aware
   opening, CR NUL, NOP keepalive). Closes F-03/04/05/12/22 and is the single
   biggest reliability gain for file transfers. M-L.
2. **Distinct dial results:** refused → `BUSY`, timeout → `NO ANSWER`, DNS
   failure → `NO DIALTONE`, honouring the X level. Terminal dialers branch on
   these for redial. S.
3. **Caller ID between RINGs** (`NMBR = <ip>`), so the BBS can log or ban by
   address itself. S.
4. **S-register fidelity:** S1 ring count, S7 wait-for-carrier, S10 carrier
   loss delay, S25 DTR detect time (replaces the fixed 5 s grace), `&D3`. M.
5. **`AT&W` / `AT&V` / `AT&Y` with a persisted profile, `AT&Zn=` stored
   numbers and `ATDS=n`.** Today they are accepted and ignored. M.
6. **Per-call telnet/raw selection** (dial modifier or phone-book flag)
   instead of guessing from the first byte. S.
7. **IPv6** for listening and dialling. The code is `AF_INET` only, including
   the blocklist. M-L.
8. **Flow control end to end:** pace output to the C64 at the line speed and
   stop reading the caller when the C64 holds RTS, instead of dropping. M.
9. **Ring indicator out of band:** drive a hardware RI pin and the ip232 RI
   code (verify against VICE's `rs232net.c` first). S.
10. **Honest TTYPE:** ask the caller's terminal type and show it on the
    dashboards; optional PETSCII ↔ ASCII translation per line for ASCII telnet
    callers. M.

### 3.2 Security

1. `Host` allowlist plus optional `Origin` check on the web console (SEC-1). S.
2. Per-IP concurrent connection and connect-rate limits on the modem port,
   independent of gate failures. S.
3. CIDR ranges in blocklist and allowlist; a growable table. S.
4. ATD dial allowlist (host / port / CIDR), default deny for loopback and
   link-local when the ip232 side is not on loopback. S.
5. PROXY protocol v2 on the caller port so real IPs survive a TCP front end. S.
6. Optional shared-secret handshake on the ip232 listener. S.
7. `umask 077` at start, `O_CLOEXEC` everywhere, self privilege drop after the
   ports and tty are open (helps macOS/launchd and non-systemd hosts). S.
8. Token redaction on every log path; a sign-on form that POSTs the token
   instead of `/?token=` in the URL. S.
9. Native TLS for the web console and a TLS listener for callers. L, and adds
   the first library dependency; nginx/stunnel in front remains the cheap path.
10. Country / ASN lists. Needs an external database; lowest priority.

### 3.3 Web console and terminal dashboard (graphics and UX)

1. **Live C64 screen mirror.** Feed the BBS→caller stream through a small
   PETSCII terminal emulator in the browser and draw a 40×25 screen with the
   16 C64 colours, per line. This answers "what is my caller seeing right now"
   at a glance and would be the signature feature of the console. Depends on
   the embedded C64 font decision (audit item 2B, still open). M.
2. **AS/400-style option column.** In both UIs, a cursor row and an `Opt`
   field per line and per blocklist entry (`4=Hang up`, `5=Details`,
   `7=Block`). Fixes F-28 properly and replaces the "first connected line"
   behaviour of F8 in the web console. M.
3. **Block, unblock and allowlist a single IP** from the callers and security
   screens. Today the only action is "clear all timed blocks", which has
   nothing to clear (F-23). S once F-23 is done.
4. **Caller history that survives.** The callers screen holds 12 entries in
   memory. Read the connection log instead: paging, filter by IP or result,
   per-IP detail (first seen, calls, failures). M.
5. **Longer-range charts in block glyphs:** hour × weekday heat map for the
   last four weeks, session-length histogram, busiest callers. Needs the
   history from item 4. M.
6. **Same screens in the TUI as on the web:** callers and traffic pages on
   F3/F4 (the TUI has main, blocklist and help only), scrollback in EVENTS. M.
7. **Session capture to a `.seq` file** per call, with replay in the web
   console at the original speed. Opt-in, same privacy warning as
   `--web-traffic`. M.
8. **Notify on connect:** terminal bell in the TUI, browser notification and
   title flash on the web. S.
9. **Metrics:** per-line byte counters, session-duration histogram,
   `tcpser_build_info`, gate result labels, blocklist size. S.
10. **Config reload on SIGHUP** for the things that are safe to change live
    (gate settings, screens, blocklist, log level). SIGHUP reopens the log
    only. M.

### 3.4 C64 link analyzer (`c64/`)

1. Userport RS-232 (KERNAL and UP9600) support; it probes 6551 cartridges at
   `$DE00`/`$DF00` only. M.
2. Automatic baud sweep that cooperates with `tcpser -Z` so both ends agree
   without key presses. M.
3. Loopback-plug test and a one-screen "report" page to photograph when
   asking for help. S.

### 3.5 Project infrastructure

1. **CI** (there is no `.github/`): build on Linux and macOS, run `make check`,
   `check-asan`, `check-tsan`. S.
2. **Tag and release 1.4.1** (latest tag is `v1.4.0`), with prebuilt binaries
   for Raspberry Pi (armhf, arm64), x86-64 Linux and macOS. S.
3. **Tests for what broke in this review:** outgoing `ATD` (success, refusal,
   timeout), telnet negotiation and split IAC, DTR/`&D`/`&C` and `-I`, S0
   auto-answer and no-answer, `-m`, multi-line routing and all-busy, allowlist
   and rate limit, ip232 re-attach, stalled peers, SIGHUP/SIGTERM. Unit tests
   for the pure parsers. M.
4. **Split the two big files:** `bridge.c` (1705 lines) into gate, blocklist,
   watchdog and bridge; `modem_core.c` command parser into a table. M.
5. Packaging: Debian package, Homebrew formula, a small Dockerfile. S each.

## 4. Suggested order

1. **Release 1.4.2, "calls don't get lost":** P1 items 1, 4, 5, 6, 9, 10, 11
   (all small), plus P2 items 12 to 23. Add the matching tests as each lands.
2. **Release 1.5, "robust line":** non-blocking caller socket, gate and dial
   off the bridge thread (P1 items 2, 7, 8), telnet state machine (item 3,
   F-12, F-22), monotonic timers, CI and release builds.
3. **Release 1.6, "console":** option column, per-IP actions, persistent
   history, C64 screen mirror with the embedded font, TUI parity.
4. **Later:** IPv6, stored profiles and numbers, flow control end to end,
   TLS, userport support in the C64 tool.

## 5. Checked and clean

XSS in the web console (all caller data goes through `textContent`); terminal
escape injection into the TUI and logs; telnet subnegotiation bounds; the AT
parser and S-registers; the config parser; webhook and `-E` hook argument and
environment handling; constant-time compares for password and token; CSRF on
the POST actions; ip232 0xFF escaping including split escapes; serial short
writes and EOF; lock ordering between logger, dashboard and web; no thread or
memory growth per call; SIGTERM with a live call (sends `NO CARRIER`, exits
0); compiler hardening flags; the systemd unit sandboxing.
